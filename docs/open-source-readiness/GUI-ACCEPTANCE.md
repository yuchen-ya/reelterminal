# Computer Use：ReelTerminal 与剪映实际操作验收

适用 G18。目标是发现真实编辑阻力和结果错误，不是模仿竞品外观，也不是用点击数量证明质量。
用户已授权在两款应用中用专用测试项目实际使用功能。测试过程不管理额度或按钟点等待。

## 1. 工具与现场

1. 在执行平台读取实际可用的 computer-use 技能及其运行时文档。Windows 原生应用必须使用能操作原生窗口的工具；浏览器自动化不能替代桌面应用验证。
2. 先做小型工具试运行：识别窗口、截图、点开非破坏性菜单、关闭菜单。失败两轮后保存证据，切换其他可执行任务。不能声称自己还在后台测试。
3. 记录 OS、分辨率、缩放、两款应用版本、ReelTerminal 构建指纹、语言、项目格式。剪映菜单随版本变化，操作以前台观测为准，不凭记忆点击。
4. 一个桌面只有一个 GUI 操作者。主会话维护 GUI 锁；测试时不同时运行另一代理抢鼠标/键盘或重启应用。
5. 已有用户项目保持原样。先检查保存状态；仅在能安全保留后创建专用测试项目。不能确认安全时该分支阻塞，继续不依赖该项目的任务。
6. 媒体创建前调用 live capabilities_get，以返回的 recommendedRoot 创建专用 job。原验收 job 仅作参考，不覆盖；源素材只读或复制到新 job。凭据只在客户端内部使用。
7. 测试材料使用自造/用户明确用于验收的素材，不上传私人视频。可用本地工具准备带时间码、色块、可辨声道、运动主体的样本；它们只是输入，不是产品输出。

## 2. 三种证据分开

- **GUI 路径**：用鼠标键盘导入、编辑、保存、导出；截图观察状态。不得通过 store、数据库、脚本或 MCP 写入来跳过被测 GUI 步骤。
- **Agent 路径**：专门验证 facade 操作后桌面实际状态，与 GUI 一致；明确标成 Agent 验收。
- **产物核验**：导出后可用媒体探测、帧/波形检查辅助验证时长、尺寸、音频及变化；命令行分析不能代替在产品里执行导出。

静态图片不能证明声音正确，媒体元数据不能证明画面正确；工具不能可靠听音时，声音主观质量标为待人工，客观静音/时长仍可测。
不把“找不到按钮”立即归因于功能不存在：尝试相关菜单/产品内帮助，记录两条已尝试路径后分类为入口不易发现或尚未找到。

## 3. 场景矩阵

每组先在 ReelTerminal 完成，再用相同素材/目标在剪映完成。无法同名对应时比较用户目标，不强行比较不同算法。
RT 专有的 Agent/工作素材流程允许剪映标“不适用”，不能因此跳过 RT 验收。

| ID | 实际任务 | 必看结果与变体 |
|---|---|---|
| U01 | 新建、改名、保存、关闭重开 | 名称/格式/媒体恢复；分别测手动保存与自动保存；切换项目 |
| U02 | 导入视频、音频、图片、多文件 | 拖入和文件选择；中文/空格文件名；不支持文件失败可见 |
| U03 | 长短时间线导航 | 30 秒/8 分钟/1 小时，适配、缩放、滚动、拖播放头与定位 |
| U04 | 分割、修剪、移动、吸附、复制、波纹删除 | 时序正确，多步撤销/重做，轨道锁定与多选 |
| U05 | 画面布局 | 缩放/位置/裁切/旋转、叠加、重构图；预览与导出一致 |
| U06 | 声音编辑 | 视频/音频轨 mute/solo、音量/淡入淡出、分离音频、闪避 |
| U07 | 本地智能处理 | G07 每项独立子场景；前后结果、进度、取消、失败与重试 |
| U08 | 字幕与文字 | 本地字幕、字幕文件导入、文字修改、字体、样式、时间范围 |
| U09 | 图形与贴纸 | SVG 可编辑导入、图像透明、变换；Agent 摄取另记 |
| U10 | 效果与转场 | 选择/应用/调整/移除，时长边界，导出不丢效果 |
| U11 | 工作素材 | 单片段与组合暂存、命名、源范围、再次上轨、实例独立、重开 |
| U12 | 自定义预设 | 文字/图形/效果/转场分别保存、跨项目应用、改名/删除 |
| U13 | 个人素材库 | 加入、删除撤销、创建撤销重做、刷新恢复、缺字节提示 |
| U14 | 外部 Agent 配音/音乐 | 两入口、任务状态、真实结果、重试不重复、切换项目后返回 |
| U15 | 帮助与浮层 | 快捷键入口、说明书查询、菜单/弹层遮挡、焦点、Esc、中英切换 |
| U16 | 导出 | 短片正常产物、取消后再导出、失败可见；用实际播放器看产物 |
| U17 | 浏览器展示 | 无桌面桥的明确说明；关云入口零请求；普通编辑/保存/导出 |
| U18 | 连贯成片 | 60–90 秒短片：至少 5 段素材、声音、字幕、图形、效果；保存重开再导出 |

U07 不是只点一次 AI 页：以 G07 最终能力清单逐项扩展。其余面板也建立功能 inventory，将每项标为已测/不适用/阻塞/未测，避免把这张场景表误称全功能覆盖。
先覆盖所有组的正常路径，再做取消/重试/边界；不因一处阻塞耗尽整轮。
剪映登录、会员、云模型不可用的功能可跳过并记录。ReelTerminal 同一功能仍然继续测。

## 4. 测试边界与恢复

- 不购买、订阅、登录新账户、安装插件/模型服务、改系统安全设置或上传素材到云端来解除阻塞。
- 既有本地能力可用即测试；模型下载若已有明确许可按现有产品流程执行，否则记录依赖，继续其他场景。不得把这些阻塞误记为产品缺陷。
- 删除只作用于本轮专用项目内的测试条目；不清浏览器全站数据、不删除用户素材、不覆盖已有导出。
- 自动化失去焦点时先截图重新识别窗口，不盲点恢复。每次关键动作后观察状态，不依靠长串固定坐标。
- 应用崩溃保留日志及最后证据，核实数据后重启；两次相同失败生成缺陷并换场景，禁止无限重启。
- 收到用户接管/停止时立即释放 GUI 锁并保存现场。客户端锁屏/断开导致操作失效时如实登记，不承诺继续。

## 5. 每个场景的证据

外部 job 中保存 `evidence/Uxx/` 与 `project/gui-matrix.json`，账本链接到该目录，不把批量截图提交到源码。

```text
场景 ID / 操作者 / 时间 / 应用及构建：
目标、输入素材指纹、项目 ID 与起始状态：
实际步骤：只写真正做过的操作
预期 / 实际：
截图：入口、关键中间状态、结果（按需要，不机械凑数）
产物路径及核验：
ReelTerminal / 剪映各自状态：passed | failed | blocked | not-applicable | untested
区别：结果差异、入口难找、操作负担、能力缺失分别记
缺陷 ID / 复现条件 / 日志位置：
剩余人工判断：主观画质、音质等
```

比较记录步骤数、意外操作和是否完成目标。耗时只有在排除模型思考、工具延迟、首次下载等干扰时才可比较，不能据此给产品做性能排名。
引用剪映截图只作私有验收证据，不自动放进公开产品手册。

## 6. 修复回路与退出

每轮 GUI 批次冻结；发现问题创建 G18-Fxxx，记录最后正常状态与最小复现。
数据丢失/错误导出优先，其次阻断、结果不一致、可发现性与视觉问题。
同一根因归并；新需求单独登记，不为了与竞品一致盲目扩功能。已授权 11 项的遗漏仍是本轮任务。
暂停 GUI → 释放锁 → 修复/独立验收/同步 → 生成新构建指纹 → 重验受影响场景。旧证据保留，注明被哪个版本取代。
全部可测任务完成或确实阻塞后交接；报告完成比例的分母必须是已登记 inventory，不能写“所有功能都测过”而没有清单。
