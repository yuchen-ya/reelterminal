# 无人值守执行规程

适用：[方案](PLAN.md)、[任务清单](TASKS.md)。这是执行规则，不是已经运行的调度系统。

## 1. 主会话职责

主会话只负责调度、授权范围内的任务拆分、文件锁、状态账本和交接，不亲自实现产品或代替子代理做验收。
主会话必须读取子代理证据，不能只转发任务后相信“完成”两个字。
必要的实现、测试、审查、文档及注释工作全部交给子代理；集成也由获写锁的子代理承担。

持续循环：

1. 恢复账本，核对当前工作区、任务状态与文件锁。
2. 选择依赖满足且未被锁定的最高优先级任务。
3. 分配具体任务卡与文件权限，启动/复用子代理。
4. 等待有界进展，检查是否超时或需要收缩任务。
5. 收到实现证据后安排独立验收、文档同步和注释同步。
6. 将阻塞项移出可执行队列，立即选择其他任务。
7. 批次冻结后安排集成，落盘进度，再进入下一批。

子代理结束不等于主会话应该结束。主会话不能因一个失败、需要用户回答的问题或某个包构建失败就结束整轮。
依赖同一阻塞的任务不反复尝试；转做其他任务、只读调查或后备队列。

## 2. 子代理与并发

逻辑角色：调查、实现、独立验收、文档同步、注释同步。
文档和注释必须分别由两个专职子代理负责，不能合并成一个“顺便更新”步骤。
角色不要求同时全部在线：服从实际并发上限，保留角色的任务与交接记录，空闲后再激活。

当前上下文若只有 4 个并发席位（含主会话），最多同时 3 个子代理。
可先运行实现/文档/注释；实现批次冻结后释放实现席位，安排独立验收。

模型遵循启动平台的显式用户配置。当前仓库给出的默认子代理配置是 `gpt-5.6-luna`、`xhigh`。
若用户在其他平台明确选择 `glm5.3-flash` 且平台支持，则按该选择执行；不得自动回落到昂贵模型。
平台没有子代理能力或模型不可用时，说明调度阻塞并保存任务包，不伪造已启动的子代理。

## 3. 一个 checkout，任何时候一个写入者

不创建新 checkout/worktree，不切换分支，不运行自动 stash/reset/clean。使用本次用户提供的当前仓库。
主会话维护全局写锁：`owner、taskId、files、startedAt`。

- 任意时刻只有一个子代理可修改仓库；文档、注释、lockfile、格式化同样算写入。
- 独立文件上的只读调查可以并行；读取正在变化的代码所得结果只能算线索。
- 验收基于冻结的 diff/内容标识；验收期间不再修改其依赖文件。
- 运行会改产物、缓存或共享资源的构建/测试应拿执行锁；桌面 GUI 同时只能有一个操作者。
- 子代理失联不立即转交写锁。先停止原执行进程、核对现场，再重新分配。

## 4. 现有修改保护

A01 保存原始 HEAD、status、文件指纹及私有备份到仓库外运行目录。备份只用于恢复证据，不自动覆盖。
A02 将旧修改逐项分类；它们始终不属于本轮自动提交范围。
碰到旧修改文件，优先只读调查；确需修改时必须证明能保留原内容并单独识别本轮差异。
无法分离就把该任务标为阻塞，继续其他任务，不要求用户半夜处理。

启动提示词授权创建仅包含已验收本轮改动的本地提交；不授权推送或合并旧工作。
只有审查、相关验收和同步通过才提交，逐文件/逐块精确暂存，禁止 `git add -u`/`git add .`/`git add -A`。
新提交前检查暂存区是否混有原内容；有歧义就不提交，保留已完成状态与明确差异。
回滚本轮改动必须按已知补丁精准操作，不能覆盖用户或其他任务内容。

## 5. 外部运行目录与账本

代码、正式文档和合理的包内测试进入源仓库；夜间运行日志、备份、大量截图不进入源树。
非媒体执行记录使用当前账户本地应用数据目录下 `ReelTerminal/agent-runs/<日期>-readiness/`，按操作系统解析绝对路径。
如果目录不可用，选择可写且位于仓库外的运行目录并记录，不静默放到仓库根目录。
生成视频或媒体验收必须先调用 live `capabilities_get`，按 `docs/AGENT-WORKSPACE.md` 使用推荐 job 根目录。
GUI/live 工具不可用则媒体验收阻塞，不擅自用 headless 替代。

建议文件：

```text
run.json                 仓库绝对路径、基线、启动时间、模型、运行状态
baseline/                私有原始差异/指纹，禁止放入公开报告
tasks/<ID>.json          精确任务卡、状态、结果摘要
reports/<ID>-<role>.md    子代理独立交接
evidence/<ID>/           命令日志与小型检查结果
PROGRESS.md              主会话维护的当前摘要
HANDOFF.md               持续更新的验收与恢复摘要
STOP                     存在时不启动新任务
```

主会话独占状态文件写入，子代理只写自己任务的报告目录。落盘使用临时文件再替换，避免半截状态。
每次派发、阻塞、验收、提交后更新账本。每批结果形成后同步更新 HANDOFF.md，使维护者随时可以验收，不等整轮结束才整理。上下文压缩后从账本恢复，不能重新做已完成任务。

## 6. 派发任务卡（每个子代理都必须收到）

```text
任务 ID / 角色：
必须阅读：PLAN.md、EXECUTION.md、对应 TASKS.md 条目、适用 AGENTS/局部说明。
问题及证据：具体文件/行为；未知则先调查，不预设缺陷。
基线：HEAD + 本轮冻结 diff/文件指纹 + 原有修改说明。
允许写入：精确文件列表；或“只读”。
目标：用户可观察结果。
不做：本任务专属范围限制。
步骤：定位→最小修改→必要验证→结果交接。
验收：确切命令/GUI步骤、预期结果、文档与注释同步对象。
时间盒：通常 30–90 分钟；同一失败最多两轮修复。
阻塞策略：记录证据与最小下一步；不得自行跨范围重构。
输出：修改列表、命令/退出码、GUI证据、未验证项、风险、报告路径。
结束：交还文件/执行锁，等待主会话安排，不自行领取其他写任务。
```

## 7. 状态及验收

状态：`pending → running → implemented → reviewing → passed`。
另有 `blocked`（当前不可继续）、`verified-no-change`（证据表明无需修改）、`deferred`（范围外）、`needs-manual-check`（人工验证未完成）。
不把 `implemented` 或 `needs-manual-check` 汇总为全部通过。
如缺陷修复产生新 diff，旧验收失效，重查受影响部分。

验收代理检查问题是否解决、是否越界、是否引入回归，必要时实际重跑关键验证。
文档与注释代理对每批分别给出“已同步/无需同步及理由/未完成”。
完整 UI/媒体行为不能仅凭 mock 测试或构建成功宣告通过。

### 已核对存在的候选命令

执行前查看最新 package.json 和工具环境。首次基线执行一次，后续按变更选择相关检查。

```text
pnpm --filter @openreel/web typecheck
pnpm --filter @openreel/web test:run
pnpm --filter @openreel/desktop typecheck
pnpm --filter @openreel/desktop test:run
pnpm --filter @openreel/agent-facade typecheck
pnpm --filter @openreel/agent-facade test:run
pnpm test:adapters
pnpm build
pnpm --filter @openreel/desktop build
pnpm --filter @openreel/desktop test:e2e
```

先读脚本与相关配置，确认不会对用户项目、安装环境或外部服务产生不期望的副作用。
依赖已齐时不重复安装；缺失依赖先使用 frozen lockfile 方式恢复，不更新 lockfile 消除错误。
不直接运行 `clean`、`deploy`、发布脚本或安装覆盖程序。打包检查须检查 hook 并禁止发布行为。
测试优先使用已有定向覆盖；不为可逆文档/小文案改动机械加测试，不为冲指标写实现镜像测试。
每条证据记录：命令、目录、时间、退出码、关键结论、基线已存在的失败和新增失败。

## 8. 长时间执行与停止

工作单项阻塞绝不是整体停止条件。还有范围内可执行任务时继续调度，不向用户发送“要不要继续”。
优先继续其他正式任务，其次后备队列；新发现的问题须有复现证据并符合 PLAN 才能生成子任务。

允许停止整轮的条件：

- 用户明确停止或出现 STOP 标记。
- 正式及有价值后备任务全部完成，或全部确有外部阻塞且无可推进调查。
- 工具/模型/客户端无法继续，或环境出现必须停止才能保护用户数据的问题。

禁止通过空转、重复检查、制造需求或忽略工具限制来满足“长时间工作”。
启动与验收时机由维护者安排。执行代理不判断时段、订阅额度或截止时间，不按时钟自行停止领任务或提前收尾。收到任务立即开始，首批验证通过后自动继续队列，无需维护者再次确认。
单任务时间盒仅用于识别卡住或过大的任务，不能作为停止整轮的理由；释放该任务后继续调度其他可推进工作。
主会话定期处理子代理进展，不进行单次超长阻塞等待；无进展先获取状态，超时则停止并核对现场。

## 9. 晨间交接格式

1. 当前 HEAD/工作区状态、本轮提交、未提交结果及与原有修改的关系。
2. passed、verified-no-change、needs-manual-check、blocked 分开统计。
3. 最重要的实际行为变化与对应证据。
4. 文档代理、注释代理的独立结论。
5. 构建/测试/GUI矩阵，平台覆盖与未验证项。
6. 最多优先列出 5 项需要维护者判断的问题，其余附录。
7. 开源候选是否就绪及具体原因；不能自动宣告已经发布。
8. 下次可直接恢复的任务 ID、锁状态、报告路径与停止原因。
