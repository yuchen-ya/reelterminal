## 1. 已确认目标

维护者只有一人。优先降低维护、审查与返工成本，利用夜间额度完成有验收依据的工作。

1. 桌面端：完善现有安装、编辑、保存、Agent 协作和导出流程。
2. 浏览器端：公开展示现有可用能力，入口诚实、失败可理解。
3. 仓库：保留有用部分，结构与配置可理解，文档可信，达到可开源水平。
4. 文档与注释：同步属于完成标准，分别安排专职子代理。

## 2. 本轮不做

- 浏览器 facade 移植、本机适配器配对、WebSocket 传输。
- SSH、多用户、服务器媒体任务、实时协同编辑。
- 全面统一引擎初始化、跨包重构、全仓重命名或格式化。
- 存储格式迁移、批量依赖升级、新模型接入、新产品功能。
- 自动发布、部署、推送、签名、改许可证或重写历史。

调查发现这些需求时，记录后续建议，不转为本轮实现。

- 不把原作者署名、包兼容名、许可证声明当作“未清理干净”的残留。

## 5. 设计决策

### 5.1 桌面端

以现有项目状态与能力为准，不重置用户打开的项目、不更改项目格式。
对每个问题先复现，定位后作最小修复。优先级：数据丢失/错误编辑 > 启动与流程阻断 > 状态错误 > 表达与布局。
Agent 的版本冲突、幂等、写入权限和历史分组语义必须保持；不能以绕过校验让测试通过。
Windows 是当前可实际验证的主要平台，其他平台没有运行证据就标为未验证。

### 5.2 浏览器端

不新增浏览器 Agent。没有桌面 bridge 时显示明确的桌面连接说明，不持续探测、不创建伪桌面 API。
按实际能力决定入口是否可用，不单凭 user-agent 判断平台。
保留正常的浏览器编辑能力；不可用入口隐藏还是禁用说明，沿用现有 UI 模式并保证用户知道原因。
素材库按站点来源及浏览器配置隔离；不声称浏览器缓存永久保存，也不声称目前已有未验证的备份能力。
新增可见文案使用项目现有 i18n；至少核对中英文，其余语言按已有回退机制处理。

### 5.3 外部依赖

先登记：用途、地址来源、触发条件、发送数据、关闭方式、失败行为。
遵循既有配置方式增加覆盖与禁用能力，默认保持已有服务行为；不得悄悄改用新服务。
关闭意味着对应功能不发请求、UI 有解释；更换 URL 不意味着服务端 API 一定兼容。
上传前说明目的和接收服务；不新增无关弹窗流程，不上传用户私有素材做自动测试。
CDN 离线化若涉及大量资源、模型重打包或部署架构变更，记录为后续，不阻塞本轮其他项。

### 5.4 文档与注释

文档代理维护用户和开发者说明，注释代理维护契约、边界、设计原因和过时 TODO。
不逐行复述实现，不对每个函数强行补注释；不得把“计划支持”写成“已支持”。
涉及 lint/type/coverage 指令、三斜线引用、source map 等特殊注释时，按有行为影响的代码改动验收。

## 6. 开源候选验收门槛

- 核心流程的结果矩阵完整；实际执行、自动化覆盖、待人工验证明确分开。
- 本轮没有引入已知的数据损坏或核心流程回归；发布阻断问题必须明确标记，不能藏在已知限制中。
- 浏览器不再出现本轮确认的永久检查或误导入口，外部依赖限制有准确说明。
- README 的主路径可按步骤验证，应用定位与包入口能找到。
- 无本轮引入的凭据、私有素材或生成媒体；检查拟公开内容和历史中的可疑项时只报告位置与类别，不输出秘密值。
- 文档与注释专项检查完成；所有变更有来源、范围和验收证据。
- 环境缺失导致的安装包/GUI/平台验证必须列为待人工验收；不得宣布“所有平台可发布”。

“开源候选就绪”与实际公开发布分开，本轮只准备候选。
