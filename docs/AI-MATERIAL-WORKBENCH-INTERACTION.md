# 批量素材快速处理器：交互设计

状态：2026-10-21 用户确认大致方向，交互细节仍可调整；未实施功能。
本文与[第一版设计](AI-MATERIAL-WORKBENCH-DESIGN.md)、[任务清单](AI-MATERIAL-WORKBENCH-TASKS.md)共同构成当前方案。

后续同日用户提供本地 React 原型，现已完成[源码接入调研](AI-MATERIAL-WORKBENCH-INTEGRATION.md)。
实际迁移优先使用该原型视图；下述批量决定、草稿、引用与交回语义保持不变。

## 1. 定位与原型依据

这是决策者批量审阅 Agent 产出的快速处理器。默认对象是一批结果，不是单份素材的制作工程。
人快速查看、筛选、轻改、标注与确认；Agent 负责收集、生成、清洗、处理和返工。
不要求每个条目依次经历“安排任务→生成→修补→采用”。

- [图片批量筛选](https://www.figma.com/proto/fAJKAxYcviYwc75mAPVmVa?node-id=2-12&starting-point-node-id=2%3A12)
- [文字审阅](https://www.figma.com/proto/fAJKAxYcviYwc75mAPVmVa?node-id=2-19&starting-point-node-id=2%3A19)
- [数据清洗](https://www.figma.com/proto/fAJKAxYcviYwc75mAPVmVa?node-id=2-21&starting-point-node-id=2%3A21)
- [视频问题帧](https://www.figma.com/proto/fAJKAxYcviYwc75mAPVmVa?node-id=5-233&starting-point-node-id=5%3A233)

当前原型包含 20 个预设状态；四类入口是独立演示路径，切换入口可能重置演示状态。
它不是动态数据产品：没有真实多选、任意文本输入、压感绘制、视频播放、删除文件或 Agent 调用。
下面的交互约定是实现目标，不能因原型有按钮就视为已实现。

## 2. 保留 ReelTerminal 外壳

保留项目标题栏、窗口控制、帮助／设置、居中模式切换、深色面板和底部状态栏。
视频编辑入口不变；新增模式名称暂沿用“AI 素材工作台”，内部按批量快速处理器组织。
不再以大标题、制作步骤向导或常驻模块配置取代现有应用外壳。

| 区域 | 默认内容 | 不应常驻的内容 |
| --- | --- | --- |
| 顶部批次栏 | 批次名、数量、处理进度、交回本轮决策 | 生成设置、模型启动按钮 |
| 左侧待处理 | 稳定队列、类型／标签筛选、多选、搜索 | 每项完整生产日志 |
| 中央查看器 | 图片网格／放大画板、语料多行列表、数据表、视频播放器 | 通用节点编辑器 |
| 右侧已处理 | 保留、修改、返工、丢弃记录，可取回 | 取代已处理区的常驻属性编辑器 |
| 底部检查器 | 来源标签、当前目标、修改建议；视频时可展开帧条／问题标记 | 固定的多轨制作时间线 |

视频帧条靠近播放器或展开到底部；不能挤掉修改建议和问题定位。
底部按内容切换，不要求图片、语料和表格都显示时间轴。

用户代码中的谱系树可作为左栏主要呈现，保留待处理／全部／返工筛选和按需二维关系图。
祖先上下文节点不自动计入可选择范围；已处理节点可保留在树原位并通过筛选查看。
右侧在“已处理”和“当前问题”之间切换，选中圈注可定位问题列表，必须保留回到整批结果的入口。
谱系树、中央查看器、二维图和已处理视图共享同一选择／决定对象，不各存一份状态。
这些是对早期固定三栏内容的细化，不增加生成节点编辑或 ComfyUI 管理。

## 3. 批次、选择与队列

1. Agent 提交一批结果，或用户导入一批内容；打开后直接浏览，不必先创建任务。
2. 单击选中／查看，Ctrl 多选、Shift 连选；图片有网格与放大两种视图。
3. 批量按钮始终显示作用范围，例如“保留 3 项”；未选中时禁用，不默认操作整批。
4. “全选”默认只选当前筛选结果，明确数量；跨页选择必须显式显示总数和范围。
5. 改变筛选后，移除不在当前结果中的选择并更新数量，避免误操作不可见条目。
6. 默认顺序固定；Agent 追加结果不抢当前项、焦点、滚动或选区。
7. 完成决定后从待处理移到已处理，按当前顺序进入下一项；自动前进可关闭。
8. 有未保存的编辑／建议时先保存草稿，不因自动前进丢内容，也不把草稿算已确认。
9. 多选操作完成后取消该组选择，下一项取原顺序中下一条仍待处理内容。
10. 筛选、切换批次、保存重开后保持各自进度；不同批次的选择和草稿不串用。

方向键导航、批量快捷键仅在列表／画布聚焦时工作。文字编辑框聚焦时尊重文本选择、
删除和撤销；Delete 不能因为用户正在删字而丢弃素材。具体保留／丢弃快捷键可在实现前确定。

源码原型目前把空格设为“点头决定”。正式接入不能全局照搬：播放器空格播放／暂停，
画布空格用于已有导航手势，输入框继续输入；只有明确的决策控件／列表焦点才响应决定快捷键。
整枝确认先显示具体条目、建议决定及将应用的修改，不能只将状态改为 modified 而不执行修改。

## 4. 统一决策与可逆操作

| 动作 | 效果 | 边界 |
| --- | --- | --- |
| 保留 | 原内容无需返工，进入已处理 | 不是默认版本采用，也不自动插入时间线 |
| 丢弃 | 本批不采用，移入已丢弃 | 不物理删除源文件，不影响其他批次引用 |
| 保存修改 | 保存衍生版本／修订，进入已修改 | 保留原图、原文或原数据 |
| 标为待返工 | 保存建议及位置，进入已处理的返工分类 | 不等于已经交给 Agent 执行 |
| 跳过／下一项 | 只改变当前查看项 | 不伪造审核结论，仍属待处理 |
| 取回／撤销 | 恢复待处理或恢复上一决定 | 修订与建议保留为草稿，不静默销毁 |

每个条目当前只有一个主决定，数量互斥计算。修订和建议是独立附属记录：
一项可以带着人工修订要求返工，此时主分类是待返工，不重复计入已修改。
已处理只是“人已作决定”，不能推断返工完成或 Agent 已接单。
批量确认是一次可撤销操作；遇到目标版本冲突时不部分提交，明确指出冲突项。
真正删除文件不在第一版快速操作里；未来若提供，应是独立动作。

## 5. 四类内容的具体交互

### 图片

- 网格批量查看，放大后连续翻图，按需固定参考并排比较。
- 放大／平移、取色、画笔、橡皮、逐笔撤销用于小细节修正。
- 圈注、箭头、短文字用于直接指出问题；它们不烘焙进素材像素。
- “像素修补”和“给 Agent 的标注／蒙版”有不同工具状态，不能混淆。
- 保存小修产生修订；画注释后可写建议并标为待返工；两者均不启动生成。
- 复杂绘画能力不进入首版；不要求每张图先画蒙版才能保留／丢弃。

### 文字语料

- 中央同时显示多条完整段落，允许多行浏览，不做一条一大页的素材卡。
- 点击行边选择整条，拖选正文选择字符范围，两种选择有不同视觉提示。
- 支持整条／多条丢弃、正文直接编辑、给选中文本添加建议。
- 修改前后可查看；原文保留，保存才进入已修改，取消编辑不改变状态。
- 文本范围固定到条目版本与字符偏移；后续改文产生新版本，不静默挪用旧批注。
- “重复语料”是提议，人工确认后才丢弃；不因相似就自动删除。

### 数据标注与清洗

- 中央为表格，支持选行、列和单元格范围；批量作用范围可见。
- Agent 的问题单元格／建议值高亮，可查看原值→建议值并逐项或批量确认。
- 可直接修改值、改标签、拒绝建议或标记返工；仅处理明确选中记录。
- 排序和筛选后仍按稳定 rowId/columnId 定位，不能按屏幕行号写错行。
- 空值、未记录来源不自动补猜；缺失与空字符串保持数据语义区别。
- 自定义清洗算法、训练管线和电子表格公式系统不属于首版。

### 视频

- 快速切换素材、播放暂停、逐帧查看；保留／丢弃可直接完成。
- 暂停时“标问题帧”记录源帧索引、PTS 和版本，可在画面上圈注。
- 连续问题可选择源区间；标记出现在帧条和问题列表，单击直接跳转。
- 问题帧截图是定位证据，不取代源帧身份；VFR 不用标称 fps 猜帧号。
- 首版重点是问题定位与交接，视频像素修复交给外部 Agent；不承诺逐帧绘画和传播。

音频不作为本轮新增必验收交互；保留已有试听能力，后续按真实需要接入同一批次协议。

## 6. 来源标签与建议引用

模型、算法、Skill、来源、批次都可以表现为标签，但底层保留类型、稳定 ID、
可得的版本与上游对象引用。来源事实与人工分类标签分别保存。
缺失显示“未记录”；Agent 提交的声明不冒充已验证执行证明。

- 标签本体点击查看详情／按此筛选；独立引用按钮把它插入建议，避免一个点击同时筛选和改文。
- 在建议框输入 `@`，选择当前素材或所选集合的标签／来源引用。
- 插入引用显示短名称，保存确定引用与展示文本；同名模型不同版本不能混为一条。
- 多选项共有标签可合并显示；值不同显示“多个值”，展开后选择具体引用。
- 批量插入建议前可见作用对象；建议可共用，也可为每项附独立区域／帧／文本范围。
- 来源详情按需展开，不常驻节点图、生成参数表或模块注册界面。
- 不可解析的引用显示失效，不静默改指向最新版本或同名对象。

示例：“这 3 张保留构图，参考 @母版 v2 的配色，沿用 @边缘清理，处理圈出的区域。”
工作台只记录意图和引用，不配置、启动、停止或管理 ComfyUI。

原型已有快捷问题卡可保留，但首版数据来自 Agent 已提交建议。原型内置的云端补全／预测按钮
不直接接入生产；请求失败不能静默展示预设建议并冒充模型判断。

## 7. 整批交回与返工回流

本地决定与草稿持续保存；“交回本轮决策”是显式发布边界。
提交前展示本轮实际条目、决定、修订、问题位置和引用标签，数量来自真实记录。
待处理和未确认草稿不进入交接；不要求全批完成后才能交回已处理子集。

发布一个不可变的 handoff 快照，带稳定条目／决定版本和幂等键。
界面区分“已保存”“已交回，等待读取”“Agent 已回报接收”；发布不等于自动发消息或启动处理。
Agent 可看见待处理进度，但默认只将明确发布的决定作为本轮执行输入。

发布后再修改决定生成新修订；不改写旧快照，不假装撤回已发生的外部执行。
通过下一次交回明确取代旧决定。重复提交同一快照不产生重复返工请求。
返工输出关联原 item/version/handoff，进入待审；已经确认的其他项不重开。
同一来源在两个批次出现时分别保留批次决定，不把一次丢弃传播到全库。

## 8. 原型与实现验收映射

| 演示路径 | 实现必须验证 |
| --- | --- |
| 图片网格→多选→保留／丢弃→撤销 | 真实选择集、数量守恒、队列移动、源文件未删除 |
| 图片放大→圈注／小修 | 注释与像素分离，坐标准确，原图保留 |
| 语料列表→修改／丢弃重复项 | 多行可读、字符选择不误选整条、保存与撤销 |
| 表格→确认两项清洗 | 稳定行列身份，原值与提议保留，不影响未选项 |
| 视频→问题帧／区间 | 源帧与时间定位正确，点击问题可返回 |
| 来源标签→插入建议 | 引用可解析，范围清楚，不串内容类型 |
| 已处理→整批交回→返工返回 | 草稿不误发、幂等发布、明确接收状态和回流关联 |

原型里的预设跳转、重复示意图、独立演示队列和静态数量只用于讨论；不作为实现数据来源。
