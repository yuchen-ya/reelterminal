## 1. 基准与边界

- 用户前端源码：`C:/Users/Administrator/Downloads/reelterminal-·-ai-素材工作台/`（下文 P）。以展开目录为基准，不使用 `.cache/reelterminal-workbench-package.zip`，后者此前确认为 HTML。
- 外壳：现有 ReelTerminal 的窗口栏、项目选择、模式导航、帮助、设置和真实权限状态。

- 不回退到原型内存状态、假媒体、伪帧号或假 Agent 返回。原型源码只读，不修改原件。

## 3. 容器与布局方案

```text
DesktopApp / Workspace                     复用已有外壳和模式分派
  WorkbenchPage                            真实状态、命令、焦点路由
    BatchToolbar                           批次、过滤、进度、交接
    工作区（无批次时也存在）
      PendingLineagePanel                  左侧队列/树，独立宽度
      主区域（纵向）
        内容区域（横向）
          当前类型查看器                   图片/视频/多行语料/数据表
          问题编辑区                       图片/视频按原型呈现
        SimpleBottomDetailsTimeline        横跨上述内容区，独立高度
    HandoffDialog / VisualMindMapModal
```

具体约束：

1. 页面拥有分隔条和尺寸状态，继续复用 `useResizable`；无需为此创建通用布局框架。组件内部不得保留第二套固定宽度、拖拽事件和游离的 body cursor 状态。
2. 图片/视频按 P 的查看器与问题看板布局还原；文字/数据按各自原型布局保留有效工作宽度，不强加原型中不存在的常驻右栏。
3. 第一轮“已处理”列表及取回能力保留为审阅切换视图，可在左侧队列的状态切换中复用；不得长期额外占据一个完整右栏挤压内容。避免另造第二份选择状态。
4. 底部详情、来源、版本与决策按钮以 P 的位置和展开/收起行为为准。四种类型共享决策语义，不要求四种页面硬套同一工具布局。
5. 宿主与原型高度不同，比较时应对齐工作区内容尺寸，不能机械复制原型 `h-screen` 或重复标题栏。记录两侧面板默认宽度、底部高度、字体、边距、工具顺序和实际差异；不要凭印象设计。
6. 复用宿主 tokens、图标、弹窗与已安装依赖。允许工作台局部样式匹配原型，禁止为还原局部背景而覆盖全局 body、字体、选中文本或滚动条。
7. 保留真实权限状态，避免再引入与项目/批次工具条重复的装饰栏；已有视频和 Motion 入口不在本轮删除。

## 4. 空态与开始入口

- 初始保留左侧待处理、中央内容、底部详情的框架；图片/视频问题区在适用的模式下显示占位。
- 中央说明“导入一批素材，或让 Agent 提交待审内容”，提供至少一个真实可执行入口。
- 优先接已有本地导入路径；如果导入后无法形成 workbench 批次，不得放一个仅打开文件对话框的假按钮。
- 若当前只能由 Agent 接入，提供“复制接入说明”：从现有文档/命令 schema 生成准确的操作说明，不嵌入 token，不自动开启写权限，不自动发消息。复制成功/失败必须有反馈。
- 来源说明、权限设置等帮助可折叠。删除“这里不提供模拟数据入口”等实现立场文案。
- 无目标时禁用发布、图谱定位等无效操作；区分无批次、筛选无结果、当前队列处理完三种状态。
- 正式项目不自动塞演示素材。视觉验收数据进入隔离测试项目，通过真实导入/ingest 路径建立。

## 5. 问题编辑与快速反馈

以 P 的 `PredictiveIssueKanban.tsx` 为交互参考：选问题 → 定位锚点 → 写建议/引用来源 → 保存或标记返工。

- 保留原型的可操作问题卡、编辑框、标签引用和上下文位置；不是把可编辑看板简化成静态汇总。
- 图片选卡对应圈注高亮；视频选卡定位已存时间并显示对应区域。删除单条问题不能清空其他问题。
- 编辑草稿按条目、版本、问题 ID 隔离；切换后不串内容。保存走现有 controller 和规范动作，失败保留草稿并呈现原因。
- 来源引用使用稳定 ID，显示名称/版本；同名不同版本可区分，引用失效有明确表现。引用 Skill 不是执行 Skill。
- 不恢复 `/api/ai/predict`、Express、Gemini、隐藏网络请求或硬编码“智能建议”。已有 Agent 建议可以展示并由人确认；没有建议时仍可手动反馈。
- 原型的建议快捷卡只有真实建议数据时才出现。移除后端预测不应同时移除手动反馈能力。
- “保存反馈”“标记返工”“发布交接”语义保持可区分，草稿不自动发布，界面不伪称 Agent 已收到。
- 图片网格快速决定、视频标记、文本范围批注、数据按选定单元格确认都要能在界面完成，不能只在 CLI 中可用。

### 验收矩阵

| 场景 | 可观察验收要求 |
| --- | --- |
| 首次进入/无批次 | 结构可见、开始入口可用、无死按钮或开发说明大段占位 |
| 图片批量 | 网格/放大切换，多选决定后正确前进，圈注→编辑建议→来源引用→保存，轻改文件保存重开一致 |
| 文字 | 多行快速浏览/选择/丢弃/编辑；重复短语第二处、emoji、跨行批注准确落在选区 |
| 数据 | 选定行/格确认，未选值不变，提议与人工值可辨；排序后仍按稳定 ID 写回 |
| 视频 | 实际播放/暂停，问题时间或区间保存，选问题回到位置，切换素材不串批注；CFR/VFR 的证据与限制分别报告 |
| 反馈与交接 | 切换对象草稿不串、保存后可读回、草稿不发布、快照含实际引用，处理项可取回 |
| 布局 | 默认/拖动/折叠/重开尺寸一致，无裁切；使用仓库实际最小支持窗口及常用桌面尺寸验证 |
| 回归 | 原视频/Motion 模式可打开；工作台不触发视频专属快捷键，输入框/播放器拥有正确键盘焦点 |

视觉证据至少包含空态、图片网格、图片问题编辑、文字多行、数据表、视频问题定位、交接预览。对每种类型提供原型和接入版相近视口的并排截图或配对文件；允许真实数据与示意素材不同，但必须解释区域/操作上的差异。不能仅交付测试数字。

沿用 `apps/desktop/e2e/README.md` 的隔离 harness；生成本地测试媒体属于开发 fixture，不触碰用户项目。运行受影响检查和必要回归；不反复执行无关全量套件。数位板压感/高 DPI 真机无法验证时，明确列出待验证项。
