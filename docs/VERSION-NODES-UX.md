# 版本节点的轻量交互设计

状态：已实施。日期：2026-10-09。文末“交互验收”清单保留为验收参考。

用户在正常剪辑时只看到一条横向节点轨迹，不需要理解工作区、revision、分叉或回收规则。用户只决定看哪个版本、是否采用这个版本；程序保证数据正确，Agent 承担阶段命名和试剪整理。本方案替代 MULTI-PROJECT-VERSIONING.md 中的常驻工作区工具栏、点击即恢复、节点名称固定及 Ctrl+S 创建节点等交互约定，保留隔离、内容不可变和引用安全的底层要求。

最新用户约定：Ctrl+S 和自动保存只保存工作区；关闭应用时按用户偏好询问或自动留存版本；项目切换仅在左上角项目菜单；切换成功后出现可点击复制的 Agent 提示；播放器对比支持历史版本。下文描述已实现的当前行为，实现细节以代码为准。

收尾范围包括克制的视觉与流畅的节点状态过渡、移除 Agent 审片自动通知，以及项目文档、内置帮助与 Agent 指引同步精简更新。这些是交付条件，不是可选的后续美化。

## 默认界面

- 时间线上方只保留紧凑横向节点轨迹，旧版本在左，新版本在右。移除重复项目选择器、默认工作区、r0、新建试剪、恢复草稿和清理按钮。
- 项目切换统一使用左上角现有项目名称下拉入口，不在节点条增加选择器。仅一个编辑方案时不出现工作区选择器。
- 节点显示为小圆点和连接线，不常驻名称、日期、卡片或说明文案。鼠标悬停和键盘聚焦时展示名称、保存日期与时间，可有一句简短变化摘要。
- 当前编辑的基准节点使用实心强调色加外环；预览节点使用不同形状的虚线外环。不能只靠颜色区分。编辑中的未保存变化沿用项目标题处的保存状态，不增加一个容易误当作存档的假节点。
- 没有节点时不占空行，也不显示“创建第一个节点”的教学文案。首次主动留存版本或按关闭偏好留存版本后自然出现；仅 Ctrl+S 不会让节点条出现。
- 主路线在一条水平线上。存在其他方案时出现短分支，最多占两个紧凑层级；更复杂关系按需展开，不能让节点区持续长高。
- 节点多时横向滚动，保持可点击面积，不压缩成难以命中的密集小点。仅主动留存版本或切换方案时定位当前节点，后台完成不能打断用户正在查看的位置。
- 细指针圆点周围有至少约 28 像素命中范围，触摸约 44 像素。视觉标记小不等于交互目标小。

## 视觉与动效

- 节点条融入现有暗色编辑界面，也适配亮色主题；没有独立大底板、卡片阴影、大面积高饱和色、发光或闪烁。连线比节点更暗、更细，不能与时间线内容争夺注意力。
- 节点默认约 6–8 个逻辑像素，保留较大的透明命中区域。当前编辑工作区的基准节点最亮，使用克制的主题强调色与细外环；其他节点使用较暗中性色，仍须看得见、找得到。
- 悬停只略微提亮；单击选中增加细微选中标识，但亮度不能冒充当前编辑节点。只读预览使用虚线外环，当前编辑节点仍保持其亮度，不因预览被错误移走。
- 不为每条分支设置强烈彩色，不给节点附带常驻名称。日期与名称在悬停浮层中保持清晰对比度，不用低透明度文字换取克制。
- 状态过渡以约 160–220 ms 的柔和减速为初始调校范围，实际以使用测试为准。优先对颜色、透明度和细外环过渡，不做弹跳、过冲、大幅缩放、波纹或持续脉冲。
- 快速连续选择可中断上一次动画，从当前视觉状态平滑过渡到新状态，不排队播放；动画不能阻塞点击、双击或键盘响应。仅预览历史，不用整条图谱重排动画。
- 节点位置稳定，新增节点局部出现，删除平滑收拢。后台生成方案时不自动滚动，不让当前节点跳动。
- 遵循系统减少动态效果偏好；关闭动效后仍能靠形状、明暗和焦点识别状态。播放视频及后台任务期间也需验证选中响应，不以空工程上的动画效果代替验收。

## 节点操作约定

| 操作 | 行为 |
| --- | --- |
| 悬停／键盘聚焦 | 显示名称、日期时间和可选一句摘要；不读取完整工程、不解码视频 |
| 单击 | 选中节点，便于键盘操作；不改工程、不切换工作区、不改变预览 |
| 双击／Enter | 预览此版本 |
| 右键／菜单键／Shift+F10 | 打开节点菜单 |
| Esc | 先关闭菜单；正在预览时返回当前编辑 |

右键菜单固定使用用户能理解的四个动作：

1. **预览此版本**。与双击一致。避免单独使用含糊的“打开”。
2. **重命名**。就地编辑名称，Enter 提交、Esc 取消。只改展示元数据，不改变工程快照、ID、父子关系、revision 或当前画面；Agent 不覆盖用户起的名字。
3. **从这里继续编辑**。唯一会将这个版本应用到当前编辑方案的操作。
4. **删除此版本**。移入版本回收站，显示可撤销通知。

触摸端点击弹出信息和动作，不把关键操作仅藏在悬停和右键里。键盘使用原生按钮聚焦顺序，不要求用户记住新快捷键；快捷键只是补充。

## 预览不会打断编辑

双击进入只读预览，使用同一个播放器与时间线展示历史内容，页面局部出现明确状态：

> 正在预览「初剪」　返回当前编辑　从这里继续编辑

- 历史时间线可以播放、拖动查看、缩放、检查属性，但不能修改。展示的是历史时间线，不能播放器是旧版而时间线仍是当前版。
- 当前工作区、撤销链、选择、播放位置、时间线缩放和滚动位置保持原状；进入预览时暂停当前播放，退出恢复原位置，默认不突然自动播放。
- 多次双击不同节点只替换只读预览内容，不创建或切换可写工作区，不产生保存节点。
- 预览使用独立只读会话。不得通过 loadProject 临时覆盖活动编辑 store，再靠切回来恢复。
- Ctrl+S 不得把预览内容保存进当前工作区。预览中按保存只提示“此版本已保存”，不隐式采用。
- Agent 可继续处理原工作区或后台试剪。用户预览期间不抢画面；退出时显示当前最新编辑结果。若进入预览前选择的片段已不存在，清除该选择，不选择其他片段冒充恢复。
- 预览只租用必要资源，退出后释放历史预览解码资源。任务和编辑中的资源保护不受影响。
- 缺失依赖时在预览中说明哪些内容无法恢复；不得画出成功结果。普通悬停不触发昂贵的完整依赖扫描。

## 从旧版继续编辑

用户点“从这里继续编辑”即明确表达采用意图，不再要求理解 checkout、工作区选择或分支命名。

程序执行：保护当前未保存内容 → 校验目标与最新 revision → 恢复该节点内容 → 开始新撤销链 → 退出预览。任一步失败不覆盖当前编辑。

正常情况下无需再弹确认框。成功提示“已回到「初剪」，之前的编辑已保留”，附“撤回本次切换”动作。此前编辑保护为可恢复草稿，不自动塞进一长串常驻节点。关闭通知后仍可在顶部项目菜单的“找回之前的编辑”中恢复。

之后继续编辑和 Ctrl+S 只更新工作区；下一次真正留存版本时才生成另一条路线，原来的后续版本继续保留。界面不弹“创建分支”对话框。

如果保护草稿期间出现并发提交，先停止采用，保留双方结果并说明当前编辑已更新；重新采用必须基于最新状态。不能在后台强行覆盖更新。Agent 可以帮助解释冲突、准备候选，但程序的校验和保存不依赖 Agent 是否在线。

## 保存保持顺手

- Ctrl+S 与自动保存使用同一工作区持久化语义；Ctrl+S 立即完成待保存写入，自动保存按既定节奏执行。两者都不创建节点、不弹节点命名窗口、不要求用户选择工作区。
- “已保存”只表示当前工作区已落盘，与“是否留存过版本”无关。必须分别维护工作区待保存状态与相对最近留存版本的内容变化；不能因为用户按过 Ctrl+S 就误判关闭时无需留存。
- 顶部项目菜单提供低频动作“留存当前版本”，供用户主动记录一个阶段；不在节点条增加常驻按钮。保存工程文件、另存为继续作为原有独立操作，不能被节点保存替代。
- 真正留存版本时自动命名“初版”或“10月9日 18:30”等简短名称，不阻塞关闭等待 Agent 起名；Agent 可依据实际修改补阶段名和摘要，用户命名优先。
- 与基准版本内容相同时不重复建节点；没有实质编辑的空工程不因关闭产生节点。
- Agent 的常规保存命令同样只保存工作区。仅明确阶段完成且任务要求留存时调用独立节点命令；失败、中断和仅生成候选不会自动产生完成节点。不能用 Agent 常规保存绕过用户的使用偏好。
- 不增加“普通模式／版本模式”开关。选择从不在关闭时留存后，不手动留存、不委托 Agent 留存的用户可以一直没有任何节点，正常剪辑路径不受打扰。

## 关闭应用时留存版本

对用户使用“留存版本”，不在退出提示中使用“节点”“快照”或“工作区”。工作区保存是必做动作，留存版本是可选动作。

默认策略为“每次询问”，仅存在值得留存的变化时弹一次：

> **关闭前留存一个版本？**
>
> 当前编辑会正常保存。额外留存一个版本，以后可以回看这次剪辑。
>
> **留存并关闭**　**直接关闭**　取消
>
> 下次关闭时：每次询问 ▾

偏好下拉与设置中的“项目与保存 → 关闭时留存版本”保持一致，提供：

| 偏好 | 行为 |
| --- | --- |
| 每次询问（默认） | 有新的可留存内容时询问一次 |
| 自动留存版本 | 有变化则保存工作区、留存版本并关闭，不询问 |
| 不留存版本，直接关闭 | 保存工作区后正常关闭，不创建节点、不询问 |

下拉明确标为“下次关闭时”，本次仍由两个动作按钮决定；按取消不提交偏好。设置随时可更改，偏好只控制关闭时留存，不禁用主动留存，不删除已有历史。

关闭规则：

- 标题栏关闭、Alt+F4 和菜单退出走同一流程；普通项目切换不触发退出询问。
- 没有变化、已经留存当前内容、没有打开工程或只有未编辑空工程时不弹询问；自动策略也不生成重复节点。
- 关闭前停止接收新的编辑提交，完成已接收事务并可靠保存所有打开项目的工作区，再处理可选留存。取消关闭恢复正常接受编辑；后台任务退出仍遵守现有任务保护，不能静默丢弃或强杀工作。
- 多个项目有待留存变化时只弹一个对话框，展开列出项目及有变化的编辑方案，默认覆盖所有有实际变化的打开工作区，不让用户理解内部工作区 ID，也不只保存前台项目。
- 工作区保存失败必须明确阻止普通关闭，不能把“不留存版本”解释为允许丢失当前工作。版本留存失败但工作区已保存时允许用户选择重试、仅保存并关闭或取消，不谎报留存成功。
- 操作系统强制终止或崩溃不能保证显示退出对话框；恢复依靠已完成的草稿持久化，不以退出提示替代自动保存。

## 左上角项目切换与 Agent 提示

左上角当前项目名称下拉统一承载项目列表、打开项目、新建项目及少量项目操作。切换成功只改变查看对象，保留各项目编辑状态、撤销链和后台任务。

每次用户主动且成功切到不同项目后，显示一次非模态可点击通知：

> 已切换到「宣传片」　**复制 Agent 提示词**

- 通知自动淡出，不要求确认，不自动复制；连续切换只保留最后一次通知，不叠加。
- 同项目内预览节点、切换编辑方案、后台任务完成和失败的项目切换都不触发项目切换提示。
- 提示词可以从左上角菜单再次复制；“弹一次”不意味着通知消失后无法找回。
- 复制内容固定对应这次成功切换的项目和实际编辑工作区，包含人类可读名称及明确 ID。执行前要求 Agent 读取最新状态、实例代次和 revision，不能把复制时的旧 revision 当作长期有效前提。
- 包含现有安全连接方式和外部工作目录指引，不包含 endpoint token 或凭据。复制提示词不自动开启写权限，也不向任何 Agent 会话自动发送消息。
- 明确告知 Agent：GUI 切换不重定向已经提交的任务；现有任务保持原目标，新的编辑请求才使用指定项目。预览或对比的历史节点不是当前写入目标。

提示词核心语义示例：

> 接下来处理项目「宣传片」（projectId: …），编辑目标为 workspaceId: …。先读取该目标最新状态、实例代次和 revision，再提交编辑；不要根据 GUI 当前画面猜测写入目标。已提交任务继续使用原目标。正常保存只保存工作区，需要留存阶段版本时再明确创建节点。

## 播放器对比历史版本

复用现有播放器“对比”入口，在选择对比来源时增加“历史版本”，与已有参考素材入口并列，不增加第二套常驻工具条。

流程：点击对比 → 选择历史版本 → 显示带名称、时间及小型关系提示的当前项目版本列表 → 选择节点 → 使用现有对比模式显示结果。

- 默认一侧为“当前编辑”，另一侧为“初剪 · 10月9日 09:32”等明确版本名，两侧来源始终可辨认。当前编辑内容变化时在提交后更新该侧，历史侧固定引用所选不可变内容。
- 在只读节点预览中进入对比时，当前观看节点作为一侧并明确标注版本名，不能把它称为“当前编辑”；可与另一历史节点比较。
- 对比读取独立只读快照，不恢复节点、不切换工作区、不修改时间线引用、不改变当前导出目标。
- 默认按相同工程时间同步，标为“按时间对齐”。沿用播放器已有的对比布局，不自动猜测镜头语义或静默移动时间轴；需要镜头对齐时使用明确的时间偏移能力。
- 一侧时长不足时显示“该版本此处无画面”，不悄悄停在最后一帧冒充同时刻画面。不同尺寸按各自画布适配显示，不修改项目尺寸。
- 默认只播放当前编辑侧的声音；历史对历史时默认播放正在预览的一侧。切换监听来源明确可见，不能两边音轨意外叠加。
- 关闭对比恢复之前的普通播放或只读预览状态，释放对比资源。项目切换退出原项目对比，不把旧节点带到新项目画面。
- 对比不是采用；需要采用时仍通过节点“从这里继续编辑”显式完成。

## 删除与重命名

用户要求的删除不是一个素材清理任务。

- 删除节点将其移入版本回收站，可撤销；不删除子节点，不改变当前编辑，不连带删除媒体。
- 被删除节点的父子信息作为内部谱系保留。需要显示连线时可以折叠经过隐藏节点的路径，但不能重写后代的真实父节点。
- 当前编辑基准节点可以从可见历史中删除，当前内容继续编辑和保存；内部基准引用保留。界面只在这种情况显示一个轻量“当前编辑”端点，它不冒充可恢复版本。
- 如果删除的是正在预览的节点，先返回当前编辑，再移入回收站。后台任务保留其固定输入。
- 名称和摘要作为可编辑元数据单独保存，快照内容继续不可变；重命名不形成新版本。
- 用户删除后显示“版本已移到回收站”，不能声称释放了素材空间。真正永久清理留在项目管理的“释放空间”，由程序验证全部引用后执行。
- Agent 可整理默认名称、提出删除建议；未经授权不自动删除用户保存或命名的版本。

## Agent 试剪的展示

Agent 负责判断是否需要隔离试剪、创建和释放临时工作区、绑定输入版本、处理冲突和保留素材。对用户统一称“方案”，不显示 workspaceId 或 revision。

正在试剪时，沿用现有 Agent 状态区域的一条轻量进度，不产生空节点。完成后把已保存的可检查方案作为弱强调的分支节点呈现，悬停注明“Agent 试剪”。双击预览，用户决定是否采用；默认不改当前编辑方案。

用户手动需要尝试另一个方向时，可在项目菜单选择“试试另一种剪法”，程序自动隔离，标题显示方案名称。只有确实存在多个编辑方案时才在项目菜单中提供选择，不常驻工作区工具条。

## Agent 审片保持安静

Agent 调用审片、帧检查、联系表或云端审片返回证据时，不在右上角自动产生通知，不自动展开结果面板，不抢焦点，也不切换播放器内容。结果继续通过工具响应和已有审片记录提供给 Agent；用户需要时从已有记录入口主动查看，不新建常驻面板。

当前通知来源已核对：`apps/web/src/desktop/editor/AgentInspectionPanel.tsx` 监听 inspection 后调用通知 store，并设置 `duration: 0`。实施时移除这条自动通知路径及仅为它服务的展开机制，清理对应失效文案和测试；不要只缩短通知时长或换一个自动弹出位置。

普通工具成功、采样限制与可由 Agent 处理的失败留在 Agent 响应及记录中。只有确实需要用户操作的问题才沿用必要通知，不因此吞掉工程保存失败等重要错误。不要为取消多余通知增加新的通知偏好开关。

该规则与项目切换的“复制 Agent 提示词”通知分开：后者由用户主动切换项目触发，按用户要求保留；审片调用本身不产生提示词或结果弹窗。

## 文档与内置帮助收尾

文档与最终代码同一轮交付，按照实际行为更新，不提前把提案写成已具备能力。先修正文档源，再生成内置帮助，最后在打包产物中核对；不能只修改导出的 HTML。

| 内容 | 核对与更新范围 |
| --- | --- |
| 用户项目文档 | `docs/USER-GUIDE.md`、`docs/MULTI-PROJECT-USAGE.md`、相关 README 和索引；统一保存、留存、预览、采用、退出偏好与对比术语 |
| 设计规格 | 本文件与 `docs/MULTI-PROJECT-VERSIONING.md`；消除旧 Ctrl+S 建节点、点击即恢复、常驻工作区栏等冲突，不让执行者从旧提案推断现状 |

精简原则：

- 用户帮助只写入口、动作、结果和必须知道的例外，不解释 store、revision、GC、幂等或工作区实例。
- Agent 指引保留目标寻址、版本保护、保存／留存区别、只读预览与对比、素材身份和工具真实限制；重复字段详情链接到 schema，不多处粘贴整份协议。
- 删除过时说明和相互冲突的示例，避免只在旧说明下面不断追加“注意”。保留数据安全和真实能力限制，不为了短而误导。
- 保存／留存、预览／采用、删除版本／释放空间使用固定词汇；“已保存”不暗示已创建历史版本。
- 文档中的命令用实际 CLI 验证；帮助中的动作在 GUI 按步骤走通。审片不弹通知后，教程不得继续要求用户点击那个弹窗。

## 性能与实现边界

精简界面不是性能保证。本方案不承诺 Git 级效率，也不引入增量存储作为前置条件。

- 节点条只读轻量摘要，悬停不加载完整快照；双击才按需加载一次。
- 合并连续编辑的草稿落盘，避免每次细小修改都排队写完整工程。显式保存、采用、退出前仍可靠 flush。
- 脏状态不应在每次拖动时完整排序和序列化工程；保存时再验证是否与基准内容相同。
- 后台事务仍执行目标、revision 和幂等约束，不能为流畅而牺牲原子性。
- 预览不会为了浏览十个节点留下十份常驻可写 store 或十套解码器。
- 普通用户路径不依赖 Agent 在线；Agent 承担组织和解释，程序承担正确性。

## 交互验收

1. 从空项目完成导入、剪辑、撤销、Ctrl+S、自动保存和导出，不出现工作区、revision、回收或分叉选择，不产生节点。
2. 空项目没有空版本行；已有节点只显示紧凑轨迹，名称日期仅在查看详情时出现。
3. 连续预览多个节点再退出，编辑内容、撤销链和视图位置保持约定，不新增工作区或节点。
4. 预览时 Ctrl+S、删除键和拖动均不隐式修改历史或当前编辑。
5. 从旧版继续编辑时自动保护脏草稿；可一键撤回切换，Ctrl+S 不建节点，主动留存后形成分叉且原后续节点仍在。
6. 删除中间节点、当前基准或正在预览节点，后代、当前工程、任务和素材不丢失；撤销删除有效。
7. 重命名不产生新版本，不修改快照；Agent 不覆盖用户名称。
8. Agent 完成方案不抢视图、不自动采用；Agent 离线仍可保存、预览、恢复。
9. 大量节点、长工程和连续拖动有改造前后对照，验证响应、写入积压、内存与磁盘增长；不以小工程验收推导大型工程效率。
10. 关闭的三种偏好与设置一致；“不留存版本，直接关闭”仍保存全部工作区。无变化不弹框、不重复留存；多项目只询问一次；失败不假成功。
11. 通过左上角切换项目后只出现一条点击复制通知，复制的目标准确且无凭据；原后台任务目标不变，通知不自动改变写权限。
12. 对比指定历史节点时来源与时间对齐清晰，无恢复、工作区切换或编辑副作用；短版本无画面处诚实显示，声音不叠加，退出与跨项目切换释放资源。
13. 视觉检查确认当前工作区基准更亮、其他节点偏暗；悬停、单击选中、只读预览和当前基准互不混淆。快速连续操作、播放时操作、亮暗主题及减少动态效果均可用。
14. 实际调用本地帧审片和可用的审片工具，返回结果时右上角无自动通知、无结果面板抢占，工具响应和记录仍完整；无可用云凭据时云端实测标记未验证，不冒充通过。
15. 从新打包应用打开内置帮助、执行实际导览、复制项目切换提示词、查询 CLI help/schema，与最终行为一致。中文英文无旧入口和旧保存语义；文档更新列入交付清单。

实现顺序：先解耦工作区保存与节点留存、实现统一关闭策略，再完成独立只读预览和原编辑保护，精简节点条并统一左上角项目切换，接入重命名、可撤销删除和播放器历史对比，移除审片自动通知并调校克制动效；最后同步精简文档与内置帮助，完成日常路径、性能及打包后验收。不能只隐藏现有工具栏却继续让双击覆盖编辑工作区。
