# AI 素材工作台第一版设计：批量快速处理器

状态：2026-10-21 修订，待实施。用户确认大致交互方向，**仅授权文档与原型，未授权执行实现任务**。
本版替代 2026-10-20 偏重单素材制作、模块注册和默认版本采用的方案。
新增类型与 CLI 名称均为提案，不代表现有能力。

关联：[交互设计](AI-MATERIAL-WORKBENCH-INTERACTION.md)、[任务清单](AI-MATERIAL-WORKBENCH-TASKS.md)、
[同类项目调研](AI-MATERIAL-WORKBENCH-RESEARCH.md)。交互细节以交互文档为准。

2026-10-21 用户提供可运行形式的 React 原型后，新增
[源码接入调研](AI-MATERIAL-WORKBENCH-INTEGRATION.md)。页面组成以用户原型为迁移起点；
本设计的数据、可逆决定与显式交回契约仍有效。实际容器边界、模拟逻辑替换和依赖适配以接入调研为准，
不再从 Figma 重新编写全部视图。当前只完成源码静态分析，未验证构建或运行。

## 1. 目标与范围

面向决策者快速处理一批 Agent 产出：查看、保留、丢弃、轻改、标问题和整批交回。
Agent 负责收集、生成、分析、处理与返工；本工具不管理 ComfyUI、模型或 Agent 的运行环境。
默认入口是批次，不需要先创建生成任务，也不强制“任务→生成→修补→采用”流程。

首版四条主路径：

1. 图片：网格筛选／放大查看，批量保留或丢弃，画板小修，直接图上标注。
2. 文字：中间多行浏览语料，选择条目或文本，丢弃、修改和附建议。
3. 数据：表格审阅、标签确认、原值与建议值比较、选定范围清洗。
4. 视频：快速查看、保留或丢弃，定位问题帧／区间，画面圈注。

所有路径均可查看并引用算法、模型、Skill、来源、批次等标签，积累一轮决定后交回 Agent。
音频沿用已有能力，不作为本轮新增必验收路径；不会为接入音频扩建新处理引擎。

不做：生成服务／模块管理器、节点编辑器、自动派工或模型安装、完整绘画软件、完整视频编辑器、
轨迹插值、多租户标注平台、任意清洗算法、电子表格公式引擎、源文件批量物理删除。

## 2. 外壳和交互结构

沿用 ReelTerminal 项目栏、窗口控制、帮助设置、居中模式切换及状态栏。
保留视频编辑；AI 素材入口替代 Motion 的主导航位置，旧 Motion 工程仍可打开。
新入口不挂载会自动创建合成的 MotionCreatorApp。

第一版继续使用现有项目／工作区保存批次和决定，允许空时间线。
不要求文字、图片或视频先成为时间线片段；不另造全局素材数据库。

| 区域 | 职责 |
| --- | --- |
| 顶部 | 批次选择、真实进度、交回本轮决策 |
| 左侧 | 待处理队列、类型／标签筛选、多选 |
| 中央 | 图片网格／轻量画板、语料多行列表、数据表、播放器 |
| 右侧 | 已保留、已修改、待返工、已丢弃，可撤销／取回 |
| 底部 | 当前目标、可引用来源标签、修改建议；按需显示视频帧条 |

详细操作、快捷键作用域、草稿、自动前进、标签引用和返工回流见
[交互设计](AI-MATERIAL-WORKBENCH-INTERACTION.md)。Figma 是 20 个预设演示状态，
并非真实编辑、播放、删除或 Agent 执行；原型状态不能冒充生产数据契约。

用户源码已加入上游谱系树、按需二维图和选区问题侧栏，接入时保留这些交互成果。
左侧树提供待处理／全部／返工视图；右侧由公共容器承载“已处理 / 当前问题”切换，
而不是让图片、视频各自内嵌整块侧栏。底部沿用原型当前实际使用的 SimpleBottomDetailsTimeline。
树／图共用条目与决定服务；“点头”仅为人工确认入口，不能根据 Agent 建议自动执行或假称修改已落地。

| [任务](../packages/core/src/types/requirement.ts)与[slice](../apps/web/src/stores/project/requirements-slice.ts) | 返工要求、引用和结果关联 | 批量反馈；不要求每个条目建一个任务 |
| [生产记录](PRODUCTION-MANAGEMENT.md) | 来源、处理声明、已有媒体版本关系 | 批次决定与事实来源分离 |
| [素材预览](../apps/web/src/components/editor/ProjectMediaPreview.tsx) | 图片／视频查看底层能力 | 网格批量审阅、待处理与已处理队列 |
| [帧工具与比较](MEDIA-REVIEW-WORKFLOWS.md) | 精确抽帧、问题证据、按需比较 | 问题帧／区域绑定当前条目版本 |
| [蒙版工具](MASK-PROPAGATION.md) | 必要时读取或导出蒙版 | 轻量修补层和独立圈注，不移植传播引擎 |
| [CLI catalog](../packages/agent-facade/src/command-catalog.ts) | 统一 schema、权限、输出与重试描述 | 批次接收、决定读取和显式交接 |
| [项目生命周期](../apps/web/src/stores/project/lifecycle-slice.ts) | 保存、历史、撤销、存档、引用保留 | 新记录纳入相同边界 |

文字语料、结构化数据表不能假装已经被 video/audio/image 的 media.import 支持。
它们使用批次条目的文本／表格载荷；复用现有文本控件和表格组件前先核实适用性，
仅为当前语料和行列编辑补最小能力。

实际原型已有 TextCorpusWorkspace 与 DataCleaningWorkspace，优先适配这两个视图，
而非再找一套大型语料／表格平台。文本定位、全表覆盖提交与隐式整表确认的问题须先修复，
详见接入调研第 5 节。

现有 ReviewRange 是 timeline 坐标；新目标使用源素材、文本版本或数据行列坐标，不能重解释旧字段。
现有 batch.start/get/resume 是分析批处理，不是人工审阅批次，保留原契约和名字。

## 4. 最小数据模型

以下为职责设计，优先扩展项目可选字段及已有引用，不建立第二套通用内容平台。

| 对象 | 最小内容 |
| --- | --- |
| ReviewBatch | ID、名称、工作区身份、顺序稳定的成员、批次修订号 |
| ReviewItem | 稳定 ID、类型 image/text/data/video、内容引用／载荷、源版本、来源标签 |
| ItemDecision | itemId、baseVersion、主决定、修订号、操作者、关联修订／反馈 |
| ContentRevision | parentVersion、修改后图／文／数据、保留的原内容 |
| Feedback | 明确 item/version 集合、位置、建议正文、结构化引用、草稿／已确认 |
| ProvenanceTag | 类型 model/algorithm/skill/source/batch、ID、显示名、可得版本、来源记录 |
| AnnotationProposal/Decision | 原提议、稳定目标、来源；独立保存人工最终值与接受／修改／拒绝 |
| Handoff | 发布的决定版本集合、反馈与修订引用、幂等键、发布时间、Agent 接收回报 |

外部 runId、模型版本、API 图等作为可选来源元数据。没有运行记录也允许接收图片、
语料和数据；不要求先注册 ModuleDescriptor、启动 RunRecord 生命周期或安装适配器。
同一媒体复用已有 mediaId；文字／表格不伪装成媒体文件或图片。

### 4.1 状态与数量

每项当前主决定为 pending/kept/discarded/modified/rework 之一，互斥计数。
右侧已处理包括 kept、discarded、modified、rework；仅表示人已决定，不表示外部返工完成。
修订与反馈附属于决定：例如带人工修订请求返工，主状态是 rework，不重复计数。
草稿与查看位置不算已处理。跳过仅切换当前项。

保留不等于默认版本采用，不写 adoptedVersionId，不更改时间线或全局素材库。
丢弃是本批逻辑决定；保留文件、其他批次引用和撤销能力。真实物理删除不在首版范围。
一次批量决定为一个历史操作；目标版本冲突时整批拒绝并显示冲突项，不部分落地。

### 4.2 位置与内容版本

- 图片区域：解码方向归一后的源像素坐标／蒙版，保存尺寸和版本。
- 视频：源解码帧索引、真实 PTS；区间为 [startFrame, endFrame)，VFR 不用标称 fps 推算。
- 文本：entryId、version、明确的字符偏移约定（首版采用 JavaScript UTF-16 半开区间）；
  选区不能拆开代理对。旧版本文本改动后，旧批注留在旧版本，不按新偏移猜位置。
- 数据：datasetId、version、稳定 rowId/columnId；排序／筛选不改变目标身份。
- 多选：保存具体 item/version 集合，不把“当前所选”作为已发布反馈的长期目标。

圈注与修改像素分别保存。画在某视频帧上的圈注不自动传播整个片段。
多帧、PNG 序列可作为带 manifest 的关联产物，不在首版增加新的序列播放器或生成管线。

### 4.3 来源标签

来源标签可查看、筛选、通过 @ 或引用按钮插入建议。类型与稳定引用保留在底层，
正文中显示短名称；同名不同版本不合并。多选不同来源显示多个值，不能冒充统一来源。
未记录如实显示；声明与实际执行证据分别呈现。来源标签不等于人工分类标签。

修改建议引用标签只表达意图，不执行模型、Skill 或外部命令。失效引用不能静默指向最新对象。
来源详情按需展开，不恢复常驻模块或参数配置界面。

## 5. 保存、撤销与交接

所有项目决定、修订、标注与发布动作使用既有 canonical Action/store 边界及身份／revision 守卫。
GUI 与 CLI 共用状态，不允许另一个后门写库。全项目替换继续遵守 ProjectState.loadProject 契约。

大媒体文件先落稳定受管位置再登记；原图／原文／原表不原地覆盖。
新引用纳入当前项目、存档及可撤销历史保留；不在时间线上也不能被回收。
文本／表格载荷同样保存重开，不能只存在 UI 内存。继续保持项目与共享素材库独立事务边界。

交回分为：本地保存 → 发布不可变 Handoff → Agent 实际回报接收。
发布只包含本轮明确决定的条目，不包括未处理项和未确认草稿；允许交回已处理子集。
外部 Agent 可读取进度，但返工默认以已发布快照为输入，避免草稿一改就触发处理。

发布后修改生成新决定版本；下一次发布明确 supersedes 旧决定，不重写旧 Handoff。
撤销本地操作不能假称撤销已发生的外部执行。相同幂等键重复发布返回同一交接。
返工结果带原 item/version/handoff 引用，作为新待审版本返回；不重开已确认的无关条目。

## 6. CLI 增量：围绕结果与决定

下列名称均为提案。沿用 reelctl call、edit.validate/edit.apply 和同一 catalog。
与旧方案相比，module.list/get/register、通用 run.report/get、默认版本 asset.adopt
移出首版必做范围；需要的来源信息通过每项 provenance 提交即可。

### 6.1 拟新增读取与接收入口

| 命令 | 内容 | 边界 |
| --- | --- | --- |
| workbench.ingest | 提交／追加批次，含稳定条目 ID、内容类型、版本、来源和可选原返工关联 | 校验受管文件／载荷，幂等接收；不启动处理 |
| workbench.get | 指定批次、条目、状态、分页，读取内容／修订／决定／来源／反馈 | 大文件返回引用；避免默认回传全批大正文 |
| workbench.changes | 工作区绑定游标，读取已保存决定／修订／发布事件 | 区分草稿、确认与发布；不是自动执行信号 |
| workbench.handoff.get | 按 handoffId 获取不可变发布清单 | Agent 执行本轮要求的稳定输入 |

新增 edit.apply op：workbench.decide（批量决定／取回）、workbench.content.update（文本／数据修订）、
workbench.repair.commit（小修文件）、workbench.feedback.save（位置与引用）、
annotation.propose/decide（提议／人工决定）、workbench.handoff.publish/ack（发布／真实接收回报）。
保留已有关联 requirement 的能力；只有需要返工任务时才使用，不为全部条目另建任务。

editor.get_context 扩展 batchId、当前条目、选择集和位置；capabilities 仅报告实际可用的查看／编辑能力。
操作者来自通道身份，不信任输入中的 actor: human。Agent 不可把自己的决定写成人工验收。

### 6.2 一致性

- 所有写入绑定 projectId/workspaceId 与已有 epoch/instance/revision 机制。
- 输入目录、尺寸、内容类型、数据字段与文本范围在外部边界校验，未知类型不能执行。
- 保存批量决定及发布都需幂等；追加不能制造重复条目，旧内容版本不能覆盖人工新修订。
- 变更游标用单调提交序号，不按时间戳；撤销／重做是新变化，过期游标明确要求重读快照。
- 发布和接收状态区别展示；没有 Agent 回报不能显示已接单／已处理。
- 外部回报不抢焦点；正在编辑的内容不被替换。

继续复用 media.import、material.*、frames.extract、frames.contact_sheet、video.compare、
analysis.get、现有小修相关工具与 history.control，各自原有限制保持不变。
不新增 HTTP 服务、常驻 Agent、自动消息、脚本运行器或 ComfyUI 配置入口。

## 7. 旧方案的保留与降级

保留：单一 GUI/CLI 状态、源版本和准确范围、提议与人工结果分离、轻量绘画、可逆操作、外部生成。
降级为按需或后续：复杂版本树、默认版本采用、生成模块目录、实时进度管理、多帧修补传播、
音频新交互、通用模块执行协议。它们不是第一版验收前置条件。

原型外壳沿用不代表要复用 Motion 专有状态；同类项目调研作为实现参考，不能扩大本次已收敛范围。

前端接入明确保留 DesktopApp/TitleBar；修改 Workspace、WorkspaceModeTabs、DesktopPage 分派，
新增 WorkbenchPage 控制器和布局。EditPage/Timeline/Preview 不整页复制。
现有启动门还承担自动保存，首轮保留，不为轻量页面草率绕开。
原型 Express/Gemini 预测服务、全局 CSS、构建配置、模拟 PTS 和内存撤销不作为生产基础迁移。

## 8. 完成标准

1. 一批图片真实多选、保留／丢弃、轻改、圈注、撤销与恢复，数量正确且不删除源文件。
2. 多条语料同时阅读，选字／选条目不冲突，修改和丢弃可撤销、原文可查看。
3. 表格排序／筛选后仍正确修改目标单元格，提议与确认分开，批量确认不误改未选项。
4. 视频问题帧／区间能返回准确位置，来源版本不漂移。
5. 来源标签可解析、可引用；多选不串模型／来源，不涉及 ComfyUI 管理。
6. 本轮实际决定与草稿分开，明确交回、幂等发布、Agent 读取并关联返工结果。
7. 项目保存、重开、撤销、历史保留与后台并发不丢记录、不抢焦点。

实施顺序见任务清单。当前只更新文档，不执行任何上述实现或验收。
