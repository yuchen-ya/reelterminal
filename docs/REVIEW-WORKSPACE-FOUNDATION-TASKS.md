## 执行规则

- 使用当前唯一 checkout；先检查 status/diff 和正在进行的任务，保留所有既有改动。不要新建 worktree、提交、推送或发布。
- 不重写已通过的反馈、修补、部分返工、快照逻辑；抽取时复用现有行为测试。原 P1 补修必须回归。
- 每批交付实际改动路径、验证命令/结果、证据与限制。先做单元/契约，再做隔离 GUI 和打包测试；不操作用户项目实例。
- 允许按明确依赖并行只读调研；同模块写入串行。本文不自动授权创建子智能体。
- 不以全量测试数量代替目标场景；没有执行的真机/平台场景明确留空。每批通过即停止扩展。

## P4：原件导出与拖出（基础交付门禁）

- [x] 实现 export.prepare/status/cancel/copy 与冻结 manifest；original/adopted/node-package 明确分离。

- [x] 大文件流式处理：正式 ReviewExportStore 准备及目标复制 269,484,063 字节二进制 IO 夹具，分块逐字节比较原件/导出/目标副本；可播放大 MP4 的 canonical 项目附加另有独立证据，不混称解码性能。
- [x] 同名冲突：同一导出内大小写冲突生成后缀，同资源重复引用去重；已有目标目录内容保持，发布到新后缀目录。
- [x] 缺失/变化源：受管副本丢失返回 MISSING_FILE，外部源变化返回 SOURCE_CHANGED，均不能拖出/复制为成功；重新准备可读资源后可恢复。
- [x] 取消：排队时及第一批字节实际写入后取消均不进入 ready、不返回成功 manifest、不允许复制/拖出；新导出 ID 可重试，源文件不变。
- [x] 磁盘不足异常：真实 WriteStream 已写入部分字节后注入 ENOSPC，另覆盖部分 manifest 写入和目标目录复制失败。无伪 ready、无半成品发布、源文件及既有目标保持、重试恢复。此为故障注入，非物理满盘。
- [x] 导出缓存生命周期：服务启动清理超过 7 天的 UUID 导出缓存，保留新缓存和受管原件；失败/取消的内部碎片沿用该缓存期限，不作为可用导出发布。
- [x] 原文件有字节保真；无文件文本/数据有明确序列化格式；节点全部范围与筛选范围明确。
- [x] 节点包导出/恢复映射验证，包含步骤与历史资源；全节点备份入口；恢复 handoff 为历史不可执行。全备份保留目录索引，当前逐节点恢复。

验收：Explorer 拖出单项/整个节点/多选；采用修补图与原件不同但各自正确；磁盘落盘逐文件摘要一致；外部拖动/删除导出副本不影响工作台；多次取消/重试不误报完成。系统拖拽交接成功不等于目标应用接收成功，报告分开。
