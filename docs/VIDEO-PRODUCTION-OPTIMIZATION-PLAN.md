# ReelTerminal 视频制作流程与算法 CLI 优化方案

日期：2026-10-03。现有改动快照：`913a6b1`。

## 目标与依据

把《DEEPSEEK的忘酌》实际制作中反复编写的抽帧、分析、局部合成、检查与回填脚本，整理为可发现、可验证、可撤销应用的产品能力。CLI、MCP 与 GUI 共用现有 Command API 和项目状态，不另建编辑器。

本次成片约 75.52 秒、30fps。实际工作包括原片分段、H3 生成、关键帧重绘、234 帧局部修复、R31 动态多轮修正，以及仅对 14 个 H3 片段的 1540 帧做模型超分。暴露的问题：

- 来源和采用版本散落在脚本、文件名、清单与聊天记录中，筛选超分范围成本高。
- 逐帧对齐、联系表、慢放和局部对比依赖外部脚本。
- 修几帧也需要手动管理帧序列、遮罩、合成、编码和回填。
- 批处理缺少统一的进度、恢复、校验及回填闭环。
- 技术检查通过不能证明动作自然；光流和网格变形曾产生明显失真。

## 实施顺序

### M0：建立差距清单与真实验证材料

1. 读取仓库 AGENTS.md、Command API、媒体检查和工作区文档。
2. 枚举已有命令、参数、runtime 支持范围、测试与打包依赖。
3. 为下面每项标注“已有／部分已有／缺失”，确定最小实现；不要因方案中有暂定名称就重复加命令。
4. 使用小型可分发测试素材验证行为；真实 PV 只用于本地辅助验收，不复制到 Git 或 CI。
5. 记录现有基线失败，不把历史问题混入本次修复。

### M1：第一批稳定算法 CLI，默认实施范围

下面名称均为能力名或候选命令名，实施时遵循现有命名与任务体系。

| 能力 | 后端 | 输入与结果 | 验收重点 |
|---|---|---|---|
| `scene.detect` | PySceneDetect Content/Adaptive | 文件或媒体、范围、少量明确参数；返回候选镜头边界与代表帧 | 硬切、渐变、闪白均有样本；结果标为候选，不自动切时间线 |
| `frames.extract` | FFmpeg | 明确帧列表或帧范围；无损 PNG 与帧映射清单 | 精确数量、顺序、首尾帧，支持含空格和中文路径，不偷改帧率 |
| `frames.contact_sheet` | 已有联系表能力优先 | 帧列表、网格、可选 ROI；带帧号的图片及映射 | 不漏选中帧、不拉伸画面、标签不盖住内容 |
| `video.compare` | 现有参考对比＋FFmpeg/OpenCV | 参考、候选、时间映射、ROI；并排、叠加或差异图，必要时慢放视频 | 明确比较原素材还是时间线渲染；颜色、时间与坐标匹配；音频来源只有一侧 |
| `patch.apply` 静态补片 | OpenCV 或现有图像后端 | 原帧、补片、遮罩、坐标；输出候选帧或片段与变更清单 | 遮罩外的无损中间帧保持不变；帧数与时序保持；编码误差另测 |
| `video.inspect` 补充检查 | FFprobe/FFmpeg | 帧数、尺寸、时间基准、黑场、冻结区间 | 技术事实和异常候选分开；不把正常停格、暗场判成失败 |

M1 的使用闭环：定位原素材范围 → 抽帧/联系表 → 导入外部修复图 → 静态遮罩合成 → 对照检查 → 通过现有 `edit.validate` / `edit.apply` / `media.replace` 回填并撤销。制作工具默认只产出候选，不隐式改时间线。

#### 公共契约

- 复用现有媒体/片段定位入口；文件输入必须通过现有路径边界验证。片段输入要明确原素材坐标与时间线坐标。
- 新的精确帧接口使用零基帧号、半开区间 `[startFrame,endFrame)`，在 schema 中明示；不要默改既有秒制接口。
- 保留源时间基准与 PTS 映射。VFR 不可直接用 `秒×名义帧率` 定位；先支持已验证的映射，未支持情况明确报错，不静默转换 CFR。
- 速度、反向、变速、定格等先检查既有映射支持；不能正确映射的组合拒绝并说明原因，不假装支持。
- ROI/遮罩注明原点、像素尺寸与坐标空间；自动旋转、裁剪、代理缩放会影响坐标，必须在清单中反映。
- JSON 沿用现有 envelope 和 artifacts 结构；包含来源、实际参数、处理方法、帧映射、产物、限制与错误码。不要为这些功能另造平行协议。
- 对比指标只用于对齐后的指定区域。不能用全画面 SSIM 判断换角色是否成功，不能用运动幅度判断动作自然。
- 长任务复用现有 job 状态、取消和产物机制。取消时停止对应子进程并管理本任务的未完成产物，不删除他人文件。
- Shell 使用参数数组，避免字符串拼接；不输出 endpoint token。模型不作为纯算法功能的隐式 fallback。
- 默认产物在外部 Agent workspace；不覆盖源文件和已交付文件。应用时沿用 revision、identity、幂等及 undo 机制。

#### 依赖与发布

优先复用安装包已有 FFmpeg/FFprobe 和原生能力。PySceneDetect/OpenCV 的 Python 封装可以先实现，但不能依赖开发者机器的 Conda 绝对路径；应明确配置、探测并在 capabilities 中报告实际可用性。

先确定最小运行方式和打包影响，再引入新运行时；无需为这一批功能重写通用插件框架。缺依赖时返回具体原因，不在用户不知情时安装大包。维护对应第三方声明，FFmpeg 的分发要求按实际构建配置核对。

### M2：运动、对齐与短段传播，后续阶段

- `motion.track`：LK 稀疏光流＋几何估计，输出点/区域轨迹、有效性、误差及失败区间。RANSAC 等估计只用于适用的几何模型。
- `image.align`：ECC 或特征匹配，在用户指定的稳定区域估计平移、相似或仿射变换，输出对齐图和残差；不默认拟合高自由度变形。
- `mask.refine`：GrabCut、膨胀/收缩与羽化。输入明确的矩形或初始标签，不承诺全自动精准人物分割。
- 短段遮罩/补片传播：采用光流并检查前后向一致性，遇到切镜、遮挡或失效区间停止传播并标记待补帧。
- 重复帧检测先做连续精确/近似重复；按人物区域检索相似姿态属于实验，不能自动替换相似帧。

验收包含快速转头、遮挡、闪白、重复停格和跟踪丢失；成功应意味着报告可信、失败可见，而非所有画面都能自动修好。成熟算法本身不代表本产品的视频传播管线已经成熟。

### M3：制作管理与 GUI 工作流，后续阶段

1. **来源记录**：扩展现有版本关系，保存原片/生成/重绘/合成/超分的实际操作、工具/模型、输入版本；混合片段可描述帧段，不强制单一标签。支持来源筛选。
2. **候选版本**：复用 `media.replace` 的历史，增加采用/待定/弃用状态及备注；不删除旧文件，GUI 与 CLI 使用同一记录。
3. **审片到看板**：选择帧段建立任务，携带参考、当前版本、截图和帧映射；提交候选后直接对比、确认、撤销。
4. **批处理**：为现有 job 增加最小批次信息。持久化每项输入、参数、状态、结果；恢复只重跑未完成或用户指定失败项。回填前检查项目是否改变，避免覆盖其他编辑。
5. **文字独立渲染**：标题、字幕、署名优先使用现有文字层，在最终分辨率渲染；不自动对烧录文字进行 OCR 或重写。
6. **帧精确替换**：在现有时间模型之上提供严格保持帧数的校验，解决浮点尾差引起的误报；不要为此一次性迁移整个项目时间存储。
7. **超分标注**：区分普通图像缩放与模型增强。模型处理属于显式外部后端，支持仅选择指定来源；不要把已有导出重采样宣传为神经网络超分。

## 暂不实施

- 不自动制作新视频或修改用户当前 PV。
- 不把 EbSynth 默认打包为成熟视频修复功能。它的公开内核不是完整时序传播管线，本次测试结果未用于最终成片；上游另有专利提示，分发前独立核实。
- 不在第一批引入 SAM2、ProPainter、生成式补帧、人物骨架、复杂网格动画或新的大型编辑软件。
- 不以“自动修动作”“一键严格复刻”为验收目标，不将本次失败的 R31 变形方案固化为默认算法。
- 不新增泛化插件系统、自动安装器、全局素材数据库或通用工作流引擎。

## 验收和交付

M1 必须包含真实可执行的 CLI/API 路径，不只写 schema、mock 或文档。至少完成：

1. 小型已知帧序列：精确抽取、联系表覆盖、输出映射、首尾和一帧片段。
2. 已知切镜/闪白/停格序列：候选检测结果和限制说明。
3. 原片与偏移候选：同步对比、ROI 与首尾边界映射。
4. 局部补片：无损中间帧的遮罩外不变、应用后其他片段不变、可撤销与恢复。
5. 错误输入：路径边界、缺文件、错误遮罩尺寸、越界范围、缺依赖；不得留下已采用但无效的素材。
6. 长任务取消与一次实际恢复；失败信息可定位到具体项。
7. live GUI 中检查候选导入、回填与撤销；无 GUI 环境时明确未验证项，不用 headless 冒充 live 验收。
8. 更新命令发现、capabilities、schema、文档及必要发行说明；运行相关测试、类型检查与构建。只修本次相关回归。

交付时报告实际新增/复用命令、验证证据、依赖安装方式、限制和提交哈希。达到 M1 验收后结束；M2/M3 是路线图，不自动扩大本次范围。
