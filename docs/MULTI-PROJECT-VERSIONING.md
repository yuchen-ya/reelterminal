# 多项目工作区与版本节点实施方案

状态：已实施。初始规格日期：2026-10-08。本文件记录底层设计：隔离、不可变节点、引用安全与 revision 保护。用户交互以 [VERSION-NODES-UX.md](VERSION-NODES-UX.md) 为准，两者冲突时以交互方案为准。

交互修订：2026-10-09 起按 [VERSION-NODES-UX.md](VERSION-NODES-UX.md) 实施。Ctrl+S、自动保存及常规 Agent 保存只保存工作区；创建节点必须是独立留存动作（项目菜单“创建存档点”、关闭时按偏好留存或 Agent `node.save`），GUI 使用右侧检查器的存档记录、只读预览与显式“从这个存档继续编辑”。本文不再重复交互约定，下文仅描述仍然有效的底层机制。

目标是一个 GUI、一个统一 CLI 宿主管理多个项目。工作区承载可变编辑状态，节点承载关键阶段的不可变完整工程描述，素材内容独立持久化并被引用。第一版完成编辑、试剪、保存、恢复、重启、查询和安全清理闭环，不做自动合并、复杂增量快照或 Git 操作界面。

## 对象与状态归属

| 对象 | 内容 | 生命周期 |
| --- | --- | --- |
| 项目 | 项目 ID、默认工作区 ID、节点关系、项目文件位置 | 持久化 |
| 工作区 | ID、所属项目、完整工程描述、`baseNodeId`、revision、草稿状态 | 持久化 |
| 工作区运行时 | 全部撤销和重做栈、变化日志、提交队列、选择状态 | GUI 切换保留 |
| 节点 | ID、所属项目、父节点、名称、摘要、完整工程描述、依赖引用、格式版本 | 不可变且持久化 |
| 素材版本 | `mediaId`、受控内容位置、内容校验信息、媒体元数据 | 独立持久化 |
| 后台任务 | 输入快照、素材版本与区间、参数、目标工作区与 revision、输出 | 按任务生命周期保存 |

- 每个项目创建一个默认工作区；首次留存版本建立根节点。
- 不为每个节点创建工作区，不强制每个 Agent 独占工作区。
- 试剪工作区按需从节点或当前工作区的固定快照建立，复制工程描述，共享素材内容。
- 节点树属于项目；每个工作区独立指向基准节点。没有保存过的工作区允许基准为空。
- 项目设置属于工程描述，恢复节点时一起恢复；项目身份不变。
- GUI 查看对象单独管理，不能决定命令的写入目标。
- 切换保留撤销链；第一版不承诺重启后恢复撤销链，但必须恢复节点和草稿。
- 完整工程描述是保存和后台执行的权威来源。前台引擎是运行时映射，不能向其他工作区保存路径提供内容。

## 路由与事务

命令明确指定 `projectId`，工作区操作指定 `workspaceId`，节点读取指定 `nodeId`。寻址与 `expectedRevision`、实例代次等保护条件分开表达。节点可读，工作区可写；写命令不得隐式恢复节点、切换 GUI 或修改历史。

每个工作区拥有独立提交队列、单调递增 revision、变化日志、幂等记录、撤销状态和草稿调度。GUI 编辑、Agent 编辑、撤销、重做、恢复和候选采用经过同一提交边界。

探测、生成和解码在队列外完成，提交前重新检查目标和 revision。一次事务的工程状态、撤销记录、revision、变化记录一起成功；失败不得发布部分编辑结果。读操作不能观察到半个事务。

Agent 写入必须带预期 revision。实例重新加载使用新的实例代次，拒绝重启前的旧请求；GUI 切换不改变代次。恢复旧节点增加 revision，不能倒退为节点当年的 revision。

幂等键按工作区隔离。同键同请求返回原结果，同键不同请求报错。节点留存和素材采用等持久写入须覆盖提交成功但回复丢失后重启的重复窗口。已成功请求的重放不得再次修改状态，也不得冒充当前最新状态。

复核现有 writer lease，避免会话级独占限制阻断多 Agent 共同编辑。宿主负责连接与路由，不引入跨项目全局编辑锁。

## 保存与恢复

### 保存与留存职责

保存（工作区落盘）与留存（创建节点）是两个职责，文档与界面文案都不得混用。

| 操作 | 行为 |
| --- | --- |
| 自动保存、生命周期保存、Ctrl+S 和 Agent 常规保存 | 合并待保存写入并持久保存工作区草稿，不创建节点。“已保存”只表示工作区已落盘 |
| 留存版本（GUI 项目菜单“创建存档点”、关闭时按偏好留存、Agent `node.save`） | 在提交边界捕获完整工程描述并与基准比较，创建不可变节点；与基准内容相同则去重，不产生重复节点 |
| 工程文件保存和另存为 | 保持现有文件能力，明确文件包含范围，与留存版本互不替代 |

`node.save` 是命令侧唯一创建节点的入口；不能把所有 `forceSave()` 调用改成创建节点。

留存版本流程：

1. 在工作区提交边界捕获完整工程描述。
2. 验证依赖持久化状态。
3. 与基准节点的持久化编辑内容比较，排除时间戳、选择、预览缓存等非编辑字段。
4. 有变化则创建父节点为 `baseNodeId` 的节点；无基准则创建根节点。
5. 一致提交节点、依赖引用和工作区基准指针，持久成功后返回节点 ID。

留存不清空撤销链。编辑后撤销到原内容再留存不产生重复节点。并发后续编辑不能被此前留存操作错误标记为已保存。未提供名称时自动命名：首个节点为“初版”，其后为本地化时间戳；名称与摘要可用 `node.rename` 单独修改，只改展示元数据，不改变快照、ID、父子关系或 revision。

保存失败不能显示已保存，也不能留下指向不完整节点的工作区指针。缺失依赖的工程允许保留描述，但必须明确标为依赖缺失，不得宣称完整可恢复。

### 节点恢复

1. 检查节点所属项目、工作区目标和预期 revision。
2. 当前工作区有脏修改时，先持久保存可找回的恢复草稿；失败停止恢复。
3. 恢复完整工程描述，清空全部撤销和重做栈。
4. 更新基准节点并增加 revision，持久记录工作区状态。
5. 仅当该工作区正在显示时更新前台引擎。

恢复草稿有明确入口、来源和时间，其依赖持续保留；不能立即被普通自动保存轮换覆盖。不维护每个节点各自的未保存状态。

例如 `A → B → C`，恢复 B 后继续编辑并留存得到 D，B 同时拥有 C 和 D 两个子节点。返回 B 只恢复 B 留存的方案，不包含之后未留存的编辑。

## 试剪结果采用

第一版采用试剪结果的完整路径是将试剪节点恢复到指定目标工作区。校验目标 revision，先保护目标草稿，然后复用节点恢复；不自动合并。采用后的编辑以该节点为基准继续。

关闭工作区只退出运行时；删除试剪工作区是显式操作，不顺带删除已留存节点。默认工作区不可删除。尚未留存节点的试剪结果须先留存才能按此路径采用。

## 素材版本与存储

- `materialId` 标识用户素材库组织记录。
- `mediaId` 标识不可变音视频或图像内容版本。
- `clipId` 标识工程描述内片段；访问时携带工作区或节点上下文。复制工作区、留存节点保留片段 ID，便于比较。

| 操作 | 行为 |
| --- | --- |
| 导入 | 登记不可变内容并返回 `mediaId` |
| 添加片段 | 引用已登记内容创建片段 |
| 替换 | 创建新版本或采用已导入候选，只切换指定工作区明确范围的引用 |
| 重新链接 | 验证内容相同后更新位置，保持 `mediaId` |
| 重命名 | 修改展示信息，内容身份不变 |
| 移除 | 移除指定工作区引用，不代表物理删除 |
| 清理 | 完整引用检查后删除物理内容 |

复用 `media.import`、`material.attach`、`edit.apply`，保持导入、素材关联、添加片段与替换引用职责清楚。现有替换时长、入出点、变速和冻结帧验证必须保留。

受控持久内容是恢复承诺的基础。GUI 与 Agent 的预览、分析、渲染和导出通过相同 `mediaId` 读取相同内容。外部路径、名称和修改时间只作为来源线索，不能证明旧版本未变。

内容身份校验放在导入、重新链接等信任边界，不在每次预览时重算大文件哈希。仅有新 ID 但仍指向可覆盖外部路径，不满足不可变版本要求。

生成结果继续放在外部 Agent 工作目录；被采用并承诺恢复的内容进入受控保留机制。节点只引用内容，不重复复制视频。素材库检索、分类、备注、精选区间继续独立于工程节点。

## 完整性与引用回收

快照覆盖现有工程契约中的时间线、文字、图形、动效、工作资产、生成 shader、工程设置及其他持久字段。字体、图片等渲染依赖也纳入完整性检查。

物理回收的保留根包括：

- 全部保留节点，包括节点素材栏内未上时间线但属于存档的素材；
- 全部工作区草稿和恢复草稿；
- 运行时撤销和重做可恢复的素材；
- 未完成任务固定输入；
- 正在登记而尚未发布的素材；
- 用户素材库承诺保留的内容。

引用索引从权威状态派生，可重建。不能根据当前或历史标签删除，也不能只相信异步索引。删除须与新增引用提交协调，避免扫描结束后素材被采用却仍遭删除。

节点启用前替换旧 GC；不得继续在切换或重载时仅按当前素材列表删除内容。查询界面可以后置，底层引用安全不能后置。

提供节点素材查询、素材被节点和草稿引用查询、节点间新增替换移除比较。区分节点留存的素材与成片实际使用的素材。

清理先产生包含具体文件、占用和依赖理由的计划，执行时再次验证引用。保留精彩区间须先生成并验证独立素材；这不会自动解除旧节点对长原片的依赖。删除长原片必须处理所有依赖节点，不得修改不可变节点后继续冒充原存档，也不得把失去依赖的节点标为完整可恢复。

## 后台任务与性能

固定输入 → 生成候选 → 登记素材 → 检查 → 显式采用 → 显式留存版本。生成成功不自动应用或建节点。

生成成功不自动应用或建节点。任务记录实际工程输入快照、素材版本与区间、参数、目标工作区与 revision。运行期间保留输入引用，不能只固定路径。采用冲突保留候选并返回冲突，不追随 GUI 重新定位。

第一版前台保留一个预览实例；闲置工作区保留轻量状态、释放解码和预览资源。后台渲染与导出使用共享有界队列，编辑提交不等待长任务完成。重启保留任务记录和已生成输出，不能续跑的任务标为中断。

旧节点按需读取。记录实际工程规模、素材规模、切换耗时、内存与磁盘占用；不将未经测量的预算当成验收结论。

## GUI

界面交互以 [VERSION-NODES-UX.md](VERSION-NODES-UX.md) 为准：时间线上方只有紧凑节点轨迹，单击选中、双击只读预览，菜单提供预览、重命名、从这里继续编辑与删除；留存入口在左上角项目菜单与关闭流程。旧提案中的常驻工作区工具栏、点击即恢复、Ctrl+S 建节点和固定节点名称均已被替代。

对本文仍然有效的内部约定：不同项目的节点树互不连接；后台任务完成或 Agent 操作不抢当前视图；预览与对比使用独立只读快照，不经过活动编辑 store；被删除节点进入回收站并可撤销，不删除子节点或素材；程序维护节点关系，用户不需要理解工作区、revision 或分叉。

## 迁移和工程文件

现有工程迁入时创建默认工作区，保留工程描述与现有素材 ID，验证登记可取得内容，缺失素材保留占位和诊断，首次留存版本建立根节点。不制造已有历史完整保留的假象。

区分应用内部项目存储与现有导出工程文件。如果文件格式仅携带当前工程，界面明确其不包含节点树；重新打开不能静默覆盖同身份已有项目。保持现有文件保存打开能力，不为本次实施扩大到完整版本库打包。
